# Roadmap

NickelInkSync syncs reading progress of sideloaded books between Kobo, Tolino
and KOReader through a KOSync server. Scope and architecture:
[SCOPE.md](SCOPE.md).

Items are grouped by effort vs. value: **quick wins** (ship fast), **high
priority** (highest value, worth the effort), and **low priority (optional)**
(nice-to-have, safe to defer); **long term** collects feasibility checks
for other device families, beyond the current scope. Effort: S = an afternoon, M = a few days,
L = a week or more, including verification.

## Quick wins

- **License** (S): replace CC BY-NC 4.0 with a software license. Why: CC
  discourages its licenses for code, and BY-NC is not GPL-compatible, which
  blocks reuse of KOReader code and redistribution alongside it. If code from
  BookOrbit's position converter is ever ported, the project has to be AGPL-3.0.

## High priority

Order: everything the Tolino Shine Color (5.18) can test on its own comes
first (reverse translation for plain EPUB, USB write-back, Qt6 symbols and
plugin). **Right after that, before anything else: the manual book
mapping in the CLI, then a desktop client with a graphical UI.**
Maintenance and bug fixes may be slotted in at any time. The Kobo (4.46:
kepub reverse translation, write-back, Qt5 plugin) follows in a pass of
its own.

- **Manual book mapping in the CLI** (M–L): link a book on a device
  (kepub, an EPUB with another hash, a Kindle KFX) to the EPUB and its
  KOReader hash, and sync through that link. Why: without the mapping
  there is no sync between kepub and EPUB and no Kindle sync. A manual
  link wins over the automatic hash match; translating the position
  between two different files needs matching chapter hrefs or a text
  anchor. Reference: BookOrbit's hash matching and position converter
  (AGPL-3.0, concept only, see the license note in
  [SCOPE.md](SCOPE.md#license)). Test case: *Heat 2* on the two reference
  devices.
- **Desktop client with a graphical UI** (L): right after the CLI
  mapping, on the same library: devices and books, creating mappings,
  starting a sync. egui/eframe (pure Rust, MIT/Apache, no WebView), one
  code base: macOS first (`.app` in a `.dmg`), then Windows (`.exe`),
  Linux optional as an AppImage built on an old glibc baseline so it runs
  on as many distributions and versions as possible. Builds are unsigned
  at first (Gatekeeper and SmartScreen warn on first start). First
  version: Tolino and Kobo (read, write back), Kindle read-only; push/pull
  per button with the `confirm` prompt; mapping suggestions by title and
  author (Kindle: `content_id`) to confirm, unmapped books listed apart;
  EPUBs from a configurable Calibre library (read-only); copying books from
  it to a Tolino or Kobo, on a Kobo optionally converted with kepubify
  (MIT), which creates the mapping kepub ↔ source EPUB automatically;
  settings dialog with the password in the system keychain; configuration
  and mappings shared with the CLI; German and English; side-by-side device
  view, restoring the database backup, sync history, release notice.
  kepubify is bundled (one binary per platform, a pinned and
  checksum-verified release, with its MIT notice).

- **Read-only device database layer** (S–M): reading the books and their
  positions is done (`status --device`); still to do: resolve
  chapters through the OPF spine and the href in `ChapterIDBookmarked`, not
  the chapter `ContentID` format. `BookID` + `VolumeIndex` only as a
  cross-check on the Kobo: Tolino chapter rows are ToC entries, so their
  `VolumeIndex` is a ToC index, not a spine index. Fixtures: the Clara BW
  and Shine Color databases in `tests/fixtures/db/`.
- **Position translation, back to the Kobo** (S–M): KOReader XPointer →
  Kobo span (kepub) and the 4.x Adobe point, for `pull` on the Kobo. Back to
  the Tolino is done (see "Recently completed").
- **USB write-back on the Kobo** (S–M): `pull --write` works on the
  Tolino (see "Recently completed"); the Kobo needs the reverse
  translation for kepub first.
- **Messages in the Tolino plugin** (S): each outcome of opening and
  leaving a book as one of Nickel's toasts, chosen by `notify` in
  `config.ini` (`all`, `errors`, `none`). Verified on the Tolino, also
  opening within the chapter last read. Still to do: English texts (the
  plugin logs `QLocale()`, `de_DE` so far).
- **Reliable take on opening, Tolino plugin** (S): two of five device runs
  opened at the chapter start, because Nickel's in-memory `Volume` cache
  does not see the row the CLI writes. The plugin now drops that cache and
  loads the book again before Nickel opens it, and in a later device test
  Nickel opened the pulled page in nine of nine runs. The plugin's check
  after opening now waits until Nickel knows its place (it often does not
  after 3 s). **Paused (28.10.):** after the Tolino updated itself to
  firmware 5.18.279364, Nickel opens at the chapter start even without
  the plugin Cause: Nickel takes the position from the table
  `tolino_bookmark`, which the CLI and the plugin do not write yet (Kobalt
  does). Next: write that row too.
- **NickelHook plugin, Qt5 (Kobo 4.x)** (L): push on book close, pull on open,
  jump via Nickel's own navigation. Blocker: find the libnickel symbol for
  "open at position" on 4.46; verification is on-device only.

## Low priority (optional)

- **Settings dialog on the device *(optional)*** (M): server, user and
  device name in Nickel instead of editing `config.ini`.
- **Sync status in the book menu *(optional)*** (M): "last synced from
  <device>, <time>", plus a manual "sync now" action.
- **Multi-device conflict view on the desktop *(optional)*** (S): `status`
  lists every device's position for a book side by side.

## Long term

Feasibility checks (each ends in a yes/no and a sketch, not in code) and
what follows from a positive one. Both families are outside the current scope (Nickel devices only, see
[SCOPE.md](SCOPE.md)).

- **Kindle ↔ KOSync: CLI and book mapping** (M): read `lpr` from the
  `.yjf` of a mounted Kindle in `status --device` and link the KFX
  (`content_id`, title, author) to the EPUB's hash; the reader and the
  translation to a KOReader XPointer are done (see "Recently completed").
  Why: the feasibility check found the position readable over USB and
  character-exact. Depends on the manual book mapping in the CLI; writing back is
  unchecked (`cc.db` and Amazon's own sync also hold the position).
  Users are assumed to have no jailbreak: the base feature set is the
  desktop CLI over USB; a jailbroken Kindle only adds to it (`cc.db`, sync
  without a cable through an on-device daemon).
- **PocketBook ↔ KOSync: feasibility check** (M): same question for the
  stock PocketBook reader. Why: PocketBook readers are common in Europe and
  open plain EPUBs, so the same file can be used on every device. To check:
  where the reader stores positions (reportedly an SQLite database on the
  device), in which format, whether it is reachable over USB, and whether
  writing it back is picked up. Blocker: a PocketBook device.
